# Medical P&O ERP

Next.js + TypeScript + Supabase (Auth, PostgreSQL, RLS). Project documentation lives in the claude.ai Project
"Ottobonm System Development" (PROGRESS, DECISIONS, TESTING, RBAC_MATRIX, ...).

## Local checks
- `npm run test:db` — applies `supabase/migrations` to a throwaway local Postgres and runs RLS tests (`supabase/tests`).
- `npm test`, `npx tsc --noEmit`, `npm run build`.

## Configuration
Copy `.env.example` to `.env.local`. Never commit secrets. The Supabase service-role key is not used by the app.

## Supabase
Migrations in `supabase/migrations` are the single source of schema truth. The test shim
(`supabase/tests/00_supabase_shim.sql`) is for local tests only and must never be applied to Supabase.

## Setting up Supabase (new empty project)
1. SQL Editor: paste and run `supabase/bundle/all_migrations.sql` once (migrations 0001-0013 in order; verified on a fresh database).
2. In Netlify set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` (never the service_role key), then redeploy.
3. Sign up from `/login`, then run `supabase/bundle/first_admin.sql` (edit the e-mail) to promote the first admin.
The bundle is generated by concatenating `supabase/migrations/*.sql`; regenerate it after adding a migration.

## Local database for trying the UI and the first sign-in (no cloud needed)
Requires Docker Desktop running and Node 22.
1. `npm install`
2. `npm run local:up`  — starts a local Supabase, applies all migrations, writes `.env.local`.
3. `npm run dev` and open http://localhost:3000/login ; sign up with any e-mail (confirmation is off locally).
4. `npm run local:admin -- you@example.com` — promotes that first account to admin (only while no admin exists). Sign in again.
5. Local Supabase Studio: http://127.0.0.1:54323 . Stop with `npx supabase stop`.
Use synthetic data only. The hosted Netlify site cannot use this local database (it is only reachable from your computer).
